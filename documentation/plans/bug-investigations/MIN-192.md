# MIN-192 Investigation

## MIN-192 — Notifications hidden by browser

### Verification Status

**Confirmed (code review).** Repro is expected on the default desktop path (`npm start` → Electron + in-app preview open in Code app). Not yet runtime-verified in this session, but the stacking behavior is explicit in the Electron preview host and matches the reported symptom.

---

### Root Cause

Menubar/topbar dropdowns are normal DOM overlays (`position: fixed`, `z-index` 50–60). The in-app preview in Electron is a **`WebContentsView`** attached to `BrowserWindow.contentView` — a **native layer above the SPA renderer**. CSS `z-index` cannot paint above it.

When Code app has the preview split open, `#previewBody` occupies the **right side of the workspace** (below the menubar). Menubar controls (notifications bell, model chip, workspace picker) are **top-right**; their popovers open downward and overlap that preview region. The native preview guest wins that overlap, so menus look “under” the browser.

This is **not** a missing `z-index` on the notifications menu. It is a **renderer vs. native view** layering conflict.

**Secondary note:** In Code + MinnowOS, the legacy `header.topbar` is hidden; chrome lives on `.mn-os-menubar`. The issue title says “notifications” but the same mechanism affects **all right-cluster menubar popovers**.

### Proposed Fix

**Do not raise CSS `z-index`** — it will not beat `WebContentsView`.

**Extend the existing preview-visibility pattern** (same as fullscreen overlays):

1. **Add chrome-popover awareness** in `preview-electron-visibility.ts`:
   - e.g. `isMenubarPopoverOpen()` or a small open-count registry
   - Return `false` from `shouldShowElectronPreviewHost()` while any obstructing popover is open

2. **Wire open/close hooks** to call `scheduleElectronPreviewHostVisibilitySync()`:
   - `src/os/notifications-menu.ts`
   - `src/os/model-chip-menu.ts`
   - `src/ui/workspace-recent-menu.ts`
   - Optional: settings search results (`.settings-search-finder__results`, `z-index: 60`), other menubar `position: fixed` menus

3. **Optional hardening:** central `registerChromePopover()` / `unregisterChromePopover()` so future menus get the behavior automatically.

4. **Out of scope for MIN-192 (unless expanded):** legacy `header.topbar` `position: absolute` menus when OS shell is off — same Electron occlusion applies; iframe-only fallback is less affected.

**Expected UX:** Preview briefly hides while a menubar menu is open, then restores on close (matches Settings/Bugs overlay behavior).
