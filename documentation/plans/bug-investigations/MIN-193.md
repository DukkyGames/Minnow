# MIN-193 Investigation

## Verification Status

**Confirmed (code trace)** — The bug is reproducible by inspection. Clicking the board header activity chip updates session state to chat view but does not repaint `#chatArea`, leaving the kanban visible while the composer reappears.

---

## Root Cause

Board → chat switching goes through `setOrchestrateViewMode('chat')` → `closeBoardGroupView()` → `switchChat(plannerChatId)`. When the planner chat is already `sessionState.activeId` (the normal case after opening board view from the sidebar), `switchChat` **returns early** without calling `renderChatFromHistory`.

Session state updates correctly (`group.viewMode = 'chat'`, `activeBoardGroupId` cleared), and `syncBoardViewChrome()` removes `main-column--board-view` (composer shows again). But `#chatArea` still contains `.board-root` because nothing triggers a chat re-render.

**Asymmetry:** Switching **to** board view calls `renderChatFromHistory`, which detects `boardGroup.viewMode === 'board'` and mounts the board. Switching **back** to chat does not mirror that when the active chat id is unchanged.

## Proposed Fix

**Primary fix (recommended):** `src/state/chat-groups.ts` — `closeBoardGroupView`

When `plannerId === state.activeId`, call `renderChatFromHistory(planner)` directly instead of `switchChat(plannerId)`:

```typescript
if (plannerId) {
  void import('../ui/sidebar').then(async (sidebar) => {
    if (plannerId !== state.activeId) {
      sidebar.switchChat(plannerId);
      return;
    }
    sidebar.renderSidebar();
    const { renderChatFromHistory } = await import('../ui/messages');
    const planner = state.chats.find((c) => c.id === plannerId);
    if (planner) renderChatFromHistory(planner);
  });
  return;
}
```

**Alternative (belt-and-suspenders):** `src/ui/view-mode-toggle.ts` — `setOrchestrateViewMode('chat')`

After `closeBoardGroupView`, call `renderChat(getActiveChat())` to mirror the board path. Less ideal because `closeBoardGroupView` is async via dynamic import.

**Secondary (init-split edge case):** If the user clicks the activity chip during board-init split streaming, also call `syncOrchestrateInitSplitChrome(getActiveChat())` from `setOrchestrateViewMode('chat')` to tear down split chrome. Lower priority than the main bug.
