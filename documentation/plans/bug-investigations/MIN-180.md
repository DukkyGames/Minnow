### Root Cause

**Primary (AI autocomplete + Quick Edit): missing model binding with silent failure**

Both AI features share `resolveEditorAiBinding()` in `src/ui/editor-ai-completion-client.ts`. It can return a provider but an **empty `modelId`** when:

1. **Follow active chat** (`useChatModel: true`, default) and the active chat has no top-bar model selected.
2. **Pin provider and model** with model left as `(use chat default)` — pinned mode allows empty `modelId`.
3. Settings show this as **`provider / —`**, which users describe as “No Model Assigned” (MIN-133).

Downstream:

- `fetchEditorAiCompletion()` sends `model: undefined` and swallows `createGeneration` errors → returns `null` with no ghost text.
- `fetchQuickEditReplacement()` returns `null` if `providerId` is empty; otherwise streams but finishes with no text and **no error message** in the panel.
- Neither path validates model before requesting.

**Contributing factors**

1. **`editorAiCompletion.enabled` defaults to `false`** — extensions are not mounted until enabled in Settings → Editor.
2. **Hard gate on local server** — AI + Quick Edit extensions only load when `getLocalServerAvailable()` is true (`file-viewer.ts`); `npm run dev` disables both.
3. **No editor role in Models hub** — `model-routing-catalog.ts` has no “Code editor AI” row; editor completions don’t pass a dedicated `fallbackRole` (server defaults to `main-chat`).
4. **Config not hot-reloaded** — editor reads `loadEditorAiCompletionConfig()` once at mount; toggling settings doesn’t affect an open tab until remount.
5. **LSP confusion** — users may say “autocomplete” for both LSP and AI; LSP needs `npm start` + LSP enabled + installed language server, not a chat model.

### Proposed Fix

**Phase 1 — Model validation + errors (fixes core MIN-180 / MIN-133 gap)**

1. Add `validateEditorAiBinding(binding): { ok: true } | { ok: false; message: string }`:
   - Require non-empty `modelId`, **or**
   - Document and implement explicit fallback (e.g. main-chat fallback chain when `fallbackChains.enabled`).
2. **Before** `createGeneration` in both clients, fail fast with a clear message:
   > “No model assigned for editor AI. Select a model in the chat bar or pin one in Settings → Editor.”
3. **Quick Edit panel:** on `result === null` after stream, append `.editor-quick-edit-panel__error` with the message (mirror offline-server path).
4. **File viewer status** (`editorAiStatusEl`): show the same message when binding invalid; don’t only show generic “AI completion failed”.
5. **Settings → Editor:** when Effective shows `—` for model, show a warning banner + link to Models / top-bar picker; in pinned mode use `includeEmptyOption: false` on model select.

**Phase 2 — Integration + UX**

6. Add **“Code editor AI”** row to `model-routing-catalog.ts` (background group) bound to `editorAiCompletion`.
7. Pass `fallbackRole: 'editor-ai'` (or `'main-chat'`) from editor clients into `createGeneration` for consistent fallback behavior.
8. Emit config-change event on `saveEditorAiCompletionConfig` → remount active file viewer editor (or update plugin config).
9. Optionally surface **LSP vs AI** in Settings → Editor overview (“Symbol completion: Language servers · AI suggestions: requires model”).

**Out of scope unless LSP also fails in repro:** LSP bundle install, master enable toggle, spawn diagnostics.

### Test Plan

1. **Unit:** `resolveEditorAiBinding` + validation — chat with/without model; pinned with/without model; pinned provider only.
2. **Unit:** Quick Edit panel renders error when `fetchQuickEditReplacement` returns `null`.
3. **Unit:** AI plugin calls `onStatus` with model-assigned message when binding invalid.
4. **Integration (manual):**
   - `npm start`, open `.ts` file, **no chat model** → enable inline completion → expect status error, not silent no-op.
   - Select top-bar model → ghost text appears after debounce.
   - Pin model in Settings → Editor → works without chat model.
   - Quick Edit (Mod-K) with selection → error when no model; diff + Accept when model set.
   - LSP: Ctrl+Space with TypeScript LSP running → completions independent of chat model.
5. **Regression:** `npm test` — `test/ui/file-editor-ai-keymap.test.mts`, new binding validation tests.

### Recommendation

Treat MIN-180 as a **reopen/regression of MIN-133’s unresolved runtime behavior**, not a new subsystem bug. MIN-133 closed the Settings visibility gap; MIN-180 needs the **request-path fix** (validate model, fail loudly, wire Models hub). LSP autocomplete should be triaged separately if it fails with a valid model and `npm start` + LSP enabled.
