## Root Cause

**Primary (shared with MIN-168):** Global theme-switch CSS animates `color` on all descendants (`body *`). In Chromium/Electron this can break text-caret/cursor painting until reload. The file editor is affected because CodeMirror content and chrome participate in that transition cascade even though `caret-color` is set on `.cm-content`.

**Primary (editor-specific):** CodeMirror 6 hides the insertion cursor unless the editor has focus. With `drawSelection()` enabled, `.cm-cursor` defaults to `display: none` and only becomes visible under `.cm-editor.cm-focused`. Any silent focus loss (Escape blur, modal, overlay, race) looks like “cursor disappeared” while the user may still believe they’re editing.

**Contributing:**

1. **Stale async mount race** — `mountEditor()` awaits language/LSP/settings before creating `EditorView`, with no guard that the tab/mount is still current. A slow open + fast tab switch can attach an editor to detached DOM or overwrite `editorView` incorrectly.
2. **Frozen CM6 dark facet** — `minnowEditorColorSchemeTheme` sets `{ dark: … }` once at module load; runtime theme changes do not reconfigure the editor.
3. **Intentional Escape blur** — `fileEditorEscapeBlurBinding` blurs the editor on Escape (by design), removing the cursor until the user clicks back in.
4. **No focus restore on tab remount** — `editorView.focus()` runs only for go-to-line/definition navigation, not on ordinary tab switches.

## Evidence

### 1. CodeMirror cursor is hidden without `.cm-focused`

From `@codemirror/view` defaults:

Minnow enables `drawSelection()` in `editor-core-extensions.ts` and styles `.cm-cursor` in `file-panel.css`, but visibility still depends on focus.

### 2. Theme transition still global (MIN-168 fix incomplete)

```3:10:src/styles/theme-transitions.css

    background-color 160ms ease,

    ...

```

MIN-168 investigation comment (Linear, 2026-06-17) describes excluding text-entry controls and setting explicit `caret-color`. That is **not** present in `global.css` / `input.css` in the current tree.

File editor already has partial hardening:

```260:289:src/styles/file-panel.css

...

.file-viewer-body .cm-editor .cm-cursor-primary {
  border-left-color: var(--mn-fg);
}
```

That helps color contrast but does not fix focus loss or Chromium transition paint bugs on `.cm-content` / descendants.

### 3. Async mount race (no stale guard)

```294:375:src/ui/file-viewer.ts
  void (async () => {
    const [langExts, useLsp, editorAiConfig, editorSettings] = await Promise.all([...]);
    ...
    editorView = new EditorView({ state, parent: editorMount });
```

No check after `await` that:
- `getActiveViewerTabPath() === path`
- `editorMount.isConnected`
- a newer mount has not started

### 4. Frozen dark facet at module init

```142:150:src/ui/codemirror-theme.ts

  { ... },
  { dark: getMode(getStoredTheme()) === 'dark' },
);
```

`applyResolvedTheme()` in `src/ui/theme.ts` refreshes hljs/xterm but **not** CodeMirror.

### 5. Escape intentionally removes editor focus

```44:50:src/ui/file-editor-keymap.ts
export const fileEditorEscapeBlurBinding: KeyBinding = {
  key: 'Escape',
  run: (view: EditorView) => {
    view.dom.blur();
    return true;
  },
};
```

### 6. Electron preview overlay — lower risk for this bug

- `preview-host.ts`: WebContentsView bounds come from `#previewBody` only.
- `file-layout.ts`: viewer and preview panes are toggled exclusively (`showViewerSplit` / `showPreviewSplit`).
- Preview can steal **window** focus when active, but should not sit on top of the CodeMirror pane while the file viewer is open.

## Proposed Fix

**Do not implement yet** — recommended patch set:

### A. Complete MIN-168 hardening (also protects file editor)

1. **`theme-transitions.css`** — Exclude from `color` transition:
   - `input`, `textarea`, `[contenteditable="true"]`
   - `.cm-editor`, `.cm-content`, `.cm-cursor`, `.cm-cursorLayer`
2. **`global.css` / `input.css`** — Add `caret-color: var(--mn-fg)` on composer and settings text fields.
3. **`init-file-panel.ts`** — Clear `document.body.style.cursor` on `lostpointercapture` / `window` `blur` (split resize already partially handles this).

### B. Editor-specific fixes

4. **`mountEditor` stale guard** — After async work:
   ```ts
   if (getActiveViewerTabPath() !== path || !editorMount.isConnected) return;
   ```
   Optionally track a monotonic `mountGeneration` token.

5. **Theme sync for CodeMirror** — Replace static `minnowEditorColorSchemeTheme` with a `Compartment` (or rebuild theme extension) and reconfigure on `syncThemeListeners` / `applyResolvedTheme`.

6. **Focus restoration** — After successful mount for the active tab, if the viewer pane is visible and the user did not explicitly blur (track a simple `hadEditorFocus` flag), call `editorView.focus()`.

7. **Optional hardening** — On `visibilitychange` / viewer pane unhide, if `document.activeElement` is inside `.cm-editor`, dispatch `EditorView.focus()` or `requestMeasure` to refresh cursor layer.

### C. Relationship to MIN-168

Link MIN-179 as **related to** MIN-168. MIN-168 addressed app-wide composer caret loss; MIN-179 is the **CodeMirror file-viewer** variant with additional focus/mounting issues.

## Test Plan

1. **Theme switch while typing in file editor**
   - Open a `.ts` file, click in CodeMirror, type continuously.
   - Switch theme family/mode 5–10 times.
   - **Expect:** insertion cursor remains visible; no reload required.

2. **Theme switch in composer (regression for MIN-168)**
   - Repeat in `#msgInput` and `#chatAppInput`.

3. **Fast tab switching**
   - Open 3+ files quickly (include one with slow language load, e.g. TS with LSP).
   - Switch tabs rapidly while typing.
   - **Expect:** cursor visible in active tab; no ghost/disconnected editor.

4. **Escape blur (expected behavior)**
   - Press Escape in editor → cursor disappears.
   - Click back in → cursor returns.
   - Document if users confuse this with the bug.

5. **Viewer ↔ preview toggle (Electron)**
   - Open file, focus editor, toggle preview, return to viewer.
   - **Expect:** cursor restored after click or auto-focus policy.

6. **Custom theme colors**
   - Enable custom colors with low-contrast fg/bg.
   - **Expect:** cursor still visible (`--mn-fg` contrast).

7. **Automated**
   - Add unit test: mock async delay in `mountEditor`; switch tab before completion; assert no `editorView` on detached node and active tab path matches.

**Platforms:** Electron desktop (`npm start`) primary; browser fallback for non-preview cases.
