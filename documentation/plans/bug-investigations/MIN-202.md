# MIN-202 Investigation

## Verification Status

**CONFIRMED** (static analysis)

The Plan → Orchestrate handoff creates a new chat, seeds a user message into history, and switches the UI to that chat — but **never starts a generation**. The user bubble appears with no assistant reply.

---

## Root Cause

`createChatWithMode()` in `sidebar.ts` treats `initialUserMessage` as “persist + render only.” It pushes the message into `chat.history` and calls `renderChatFromHistory()`, but does **not** invoke `runChatTurn()` or `sendMessageWithTools()`.

Working auto-send paths elsewhere:

- **`code-launch.ts`**: creates chat, puts seed in composer, calls `sendMessageWithTools()`
- **`orchestrate-board.ts` `sendBoardMessage()`**: sets composer, calls `sendMessage()`

The mode-handoff path (`create_chat_with_mode` → `executeCreateChatWithMode` → `createChatWithMode`) only does the history push. `bootGenerationResumeForChat()` is a no-op for new chats (no `currentGenerationId`).

**Expected flow (broken):**

1. Plan agent calls `propose_mode_switch` (`situation: plan_complete`)
2. User picks **New Orchestrate chat**
3. Model calls `create_chat_with_mode` with `mode_id: orchestrate`, `plan_path`, and usually `initial_user_message` (e.g. `Execute plan at documentation/plans/foo.md`)
4. New Orchestrate chat activates; user message renders
5. **Missing:** kick off `runChatTurn` on the new chat → no assistant response

## Proposed Fix

### Step 1 — Add kickoff helper (new function in `sidebar.ts` or `src/chat/mode-handoff-kickoff.ts`)

After seeding history, start generation with `pushUser: false` (message already in history):

```typescript
/** Start LLM turn for a chat that already has a seeded user message in history. */
async function kickoffSeededChatTurn(chat: Chat, message: string): Promise<void> {
  const { detectLocalServer } = await import('../tools/client');
  const { runChatTurn } = await import('../tools/loop');

  await detectLocalServer();
  await runChatTurn({
    chat,
    pushUser: false, // user row already pushed by createChatWithMode
    rawText: message,
    userText: message,
    displayText: message,
    historyContent: message,
    skillId: null,
    validAttachments: [],
    titleSeed: message,
    shouldScheduleTitle: true, // first user message was pre-seeded
    ownsGlobalStreaming: chat.id === getActiveChat().id,
  });
}
```

### Step 2 — Wire into `createChatWithMode` (`sidebar.ts` ~L762–788)

```typescript
const initial = options.initialUserMessage?.trim();
if (initial) {
  chat.history.push({ role: 'user', content: initial });
  recordChatMessage(chat);
}

// ... existing activate/render/sync ...

if (initial) {
  void kickoffSeededChatTurn(chat, initial).catch(() => {
    /* runChatTurn surfaces inline errors */
  });
}
```

Use `void` + fire-and-forget so synchronous callers (tool loop) are not blocked. Concurrent streams are allowed (`isBackgroundStreamBlockingSend()` returns `false`).

### Step 3 (optional UX hardening) — Default seed for Orchestrate + plan, no explicit message

When `modeId === 'orchestrate'`, `orchestratePlanPath` is set, and `initialUserMessage` is omitted, default to:

```typescript
`Execute plan at ${chat.orchestratePlanPath}`
```

This matches prompt guidance and covers models that skip `initial_user_message`.

### Step 4 — Do **not** change `code-launch.ts`

It intentionally avoids `initialUserMessage` and uses composer + `sendMessageWithTools()` — keep that path as-is.
