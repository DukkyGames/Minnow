# MIN-199 Investigation

## MIN-199 — Context window not loading for OpenAI API providers

### Verification Status

**Confirmed (code analysis).** The bug is reproducible by tracing the context-limit resolution path for any provider with `apiKind: 'openai-v1'` (OpenAI, OpenRouter, Groq, etc.).

**Observed behavior:**
- Context usage ring shows `context-usage-ring--unknown-limit` — tooltip says **"Context limit unknown"**, ring fill stays at 0%.
- Bottom stats strip `#iCtx` shows **"—"** instead of a token count.
- Token *usage* estimates still work; only the **model limit** is missing.

**Why LM Studio works but OpenAI does not:** LM Studio (`lm-studio-v0`) normalizes `max_context_length` / `loaded_context_length` from `GET /api/v0/models`, and completions can populate `chat.modelInfo.context_length` via SSE `model_info`. Neither path exists for standard OpenAI API providers.

---

### Root Cause

Two gaps in the OpenAI provider pipeline leave `resolveContextLimit()` with no limit:

#### 1. Server strips context metadata for `openai-v1`

`proxyModels()` → `normalizeModelsResponse('openai-v1', …)` in `server/providers/paths.js` only preserves `id`, `type`, and `state`. Any upstream context fields are discarded:

```129:142:server/providers/paths.js
  const data = raw.map((item) => {
    if (typeof item === 'string') {
      return { id: item, type: 'llm', state: 'loaded' };
    }
    if (item && typeof item === 'object' && 'id' in item) {
      const row = /** @type {{ id: string, type?: string, state?: string }} */ (item);
      return {
        id: row.id,
        type: row.type || 'llm',
        state: row.state || 'loaded',
      };
    }
    return { id: String(item), type: 'llm', state: 'loaded' };
  });
```

By contrast, `normalizeLmStudioModelRow()` preserves `max_context_length` and `loaded_context_length`.

#### 2. No known-model fallback for cloud APIs

The standard OpenAI `/v1/models` response does **not** include context window size (only `id`, `object`, `created`, `owned_by`). Minnow has no equivalent of Odysseus’s `KNOWN_CONTEXT_WINDOWS` table in `documentation/reference/odysseus-dev/.../model_context.py`.

#### Resolution chain (all sources empty for OpenAI)

```144:157:src/chat/context-usage.ts
export function resolveContextLimit(modelId: string, chat: Chat): number | null {
  const fromChat = chat.modelInfo?.context_length;
  if (typeof fromChat === 'number' && Number.isFinite(fromChat) && fromChat > 0) {
    return fromChat;
  }

  const cached = getModelRowForSelectOrCanonicalId(modelId);
  if (cached) {
    const fromRow = contextLengthFromModelRow(cached);
    if (fromRow != null) return fromRow;
  }

  return null;
}
```

For OpenAI:
| Source | Result |
|--------|--------|
| `chat.modelInfo.context_length` | Never set — OpenAI SSE has no `model_info` |
| `capabilities.contextLength` | `null` — derived from empty row |
| `loaded_context_length` | Absent (openai rows default `state: 'loaded'` but carry no length) |
| `max_context_length` | Absent — stripped at proxy |

### Proposed Fix

**Do not implement yet** — recommended two-layer approach (mirrors Odysseus):

#### Layer A — Preserve upstream metadata (server)

Add `normalizeOpenAiModelRow()` in `server/providers/paths.js` (parallel to `normalizeLmStudioModelRow`) that extracts context from common field aliases:

- Top-level: `context_length`, `context_window`, `max_context_length`, `max_model_len`, `max_seq_len`
- Nested: `meta`, `model_extra` (OpenRouter-style extensions)

Map the first positive numeric value to `max_context_length` on the normalized row.

#### Layer B — Known-model lookup (client)

Add `src/lib/known-context-windows.ts`:

- Port `KNOWN_CONTEXT_WINDOWS` from Odysseus (`model_context.py`)
- Implement `lookupKnownContextLength(modelId: string): number | undefined` with **longest-key-wins** substring matching (avoids `o1` shadowing `o1-mini`)
- Strip provider prefixes (`openai/gpt-4o`) and suffixes (`:free`)

Integrate as final fallback in `contextLengthFromModelRow()` (or `resolveContextLimit()`):

```
capabilities.contextLength → loaded_context_length → max_context_length → lookupKnownContextLength(id)
```

Set `capabilities.sources.contextLength = 'known'` when the lookup supplies the value.

#### Layer C — Tests & docs

- `test/providers/paths.test.js`: openai-v1 row with `context_length: 128000` → `max_context_length: 128000`
- `test/lib/known-context-windows.test.mts`: `gpt-4o-mini` → 128000, `o1-mini` → 128000 (not 200k)
- `test/chat/context-usage.test.mts`: `resolveContextLimit('gpt-4o', chat)` returns 128000 via known table
- Update `documentation/context.md` § Context window usage to document openai-v1 known-model fallback

**Out of scope for v1:** Per-endpoint `/models` re-query at send time (Odysseus does this for local endpoints); capability probe does not discover context length today.
