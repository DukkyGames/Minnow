# MIN-188 Investigation

## MIN-188 — Dev Server issues

### Verification Status

**Confirmed (reproducible by code inspection).** The issue matches the Linear description: users can get stuck in `starting` (or a misleading optimistic `starting` UI after a failed managed start) with no way to cancel from the hub.

| Layer | Stop capability |
|--------|-----------------|
| Backend `POST /api/workspace/dev-server/stop` | Works for `starting` and `running` when a `runId` exists |
| Hub primary cell click | Stop only when `running`; **blocked** when `starting` / `stopping` |
| Dev server Console tab | Log stream + Clear only — **no Stop** |
| Preview panel | Open URL only — unrelated to lifecycle |

---

### Root Cause

The hub dev-server cell uses a **start/stop toggle on the primary cell**, but the view model and click handler **only allow stop in `running`**. During `starting` and `stopping`, the cell is disabled and clicks are ignored.

Secondary gaps:

1. **No starting timeout** — if `healthUrl` is set but never becomes healthy, status stays `starting` indefinitely (no promotion to `error`).
2. **Shell sub-agent fallback** — when managed `POST …/start` fails, a shell sub-agent is spawned; there is no cancel/stop path tied to `startAgentRunId`.
3. **`error` state** — primary click restarts; if a background process exists (e.g. via agent), there is no explicit stop affordance.

The backend already implements stop for stuck starts; the bug is primarily **UI / UX wiring**, not missing server API.

### Proposed Fix

**Phase 1 — UI stop for stuck starts (minimal, fixes core bug)**

1. **`deriveHubDevServerView`** — set `primaryDisabled: false` for `starting` when `runId` is present (or always for `starting`). Optionally change meta to `starting… · click to stop`.
2. **`handlePrimaryClick`** — remove the early return for `starting`; route `starting` → optimistic `stopping` + `postDevServerStop()` (same as `running`).
3. **`error` state** — if `status.runId` or `managedRunId` exists, primary click should **stop** first; otherwise keep restart behavior.
4. **Tests** — update `hub-dev-server.test.mts`; add API test `stop while starting` in `dev-server-api.test.js`.

**Phase 2 — Hardening (recommended)**

5. **Starting timeout** in `getDevServerStatus` / `reconcileRow` — e.g. if `starting` for >120s with `healthOk === false`, transition to `error` with message `"Health check timed out"` (still stoppable via Phase 1).
6. **Agent fallback cancel** — on stop, if `startAgentRunId` is set, call `cancel_sub_agent` (or equivalent) so shell fallback cannot leave orphan processes.
7. **`startDevServer` idempotency** — guard against duplicate spawns when already `starting` with active `runId` (currently only `running` is guarded).
8. **Dev server Console tab** — optional **Stop** button when `managedRunId` is active (calls `postDevServerStop()`), mirroring agent terminal Stop.

**Phase 3 — UX polish (optional)**

9. Dedicated **`#hubDevServerStop`** button visible during `starting` / `running` / `error`+run, so users do not rely on toggle semantics.
10. Update `documentation/context.md` with stop-during-starting behavior.

**Out of scope:** Preview panel stop (preview is read-only navigation); Minnow’s own Vite process (`npm start`) — separate from workspace dev server.

### Test Plan

1. **Stuck starting (health never passes)**  
   - `startup.md` with `healthUrl` pointing at a closed port  
   - Start from hub → stays `starting`  
   - Click primary (or Stop) → `POST …/stop` → status `stopped`, process killed, port free  

2. **Stop while `starting` (API)**  
   - Start with `healthUrl`; before health server listens, `POST …/stop`  
   - Assert `stopped`, no orphan `runId`  

3. **Running stop (regression)**  
   - Start without `healthUrl` → `running` → click stop → `stopped`  

4. **Error + restart**  
   - Invalid `command` in `startup.md` → `error` with no `runId`  
   - Click primary → restart attempt (no stop call)  

5. **Agent fallback**  
   - Force managed start failure → shell sub-agent spawns  
   - Stop from hub → sub-agent cancelled + any registered dev-server run stopped  

6. **Console tab**  
   - During `starting`, Console shows logs; after Phase 2, Stop kills process  

7. **Automated**  
   - `npm test` — extend `hub-dev-server.test.mts`, `dev-server-api.test.js`  
   - `npx tsc --noEmit`
