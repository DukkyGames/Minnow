# MIN-182 Investigation

## MIN-182 — Orchestrator board won't close

### Verification Status

**Confirmed (static code analysis)** — matches the Linear description and repro notes. No code changes were made.

The failure path is reproducible when the board is opened while a **non-folder** chat is still `activeId`. Clicking that same sidebar row (or any chat equal to `activeId`) hits an early return in `switchChat` before board teardown or re-render. The reported workaround—select a chat inside the orchestrate folder first—works because that chat has a different id, so `switchChat` runs past the guard and clears `activeBoardGroupId`.

---

### Root Cause

Three interacting gaps in board/session coordination:

1. **`switchChat` early-return ignores an open board**  
   When `id === sessionState.activeId`, `switchChat` returns immediately without dismissing the board or re-rendering chat (`src/ui/sidebar.ts` ~672–675). Board dismissal logic (~686–691) never runs.

2. **Board dismissal targets the wrong folder**  
   When leaving board view, `switchChat` only sets `viewMode = 'chat'` on the **destination** chat’s group (`chat.boardGroupId` / `chat.groupId`). The **currently open** board group (from `activeBoardGroupId`) is not reset when switching to an outside-folder chat. `activeBoardGroupId` is cleared, but the open group can remain `viewMode: 'board'` (stale persisted state).

3. **`openBoardGroup` does not retarget planner for external active chats**  
   Planner focus only happens when the active chat is already **inside** the board folder (~185–190). If the user opens the board from a sidebar folder header while on an external chat, `activeId` stays on that external chat, the board mounts, and sidebar highlight is suppressed (`sidebarHighlightChatId` returns `null` while board is open ~167–171). Clicking the external chat again is a no-op (cause #1).

**Secondary:** `closeBoardGroupView` calls `switchChat(plannerId)` after clearing board state (~217–219). If `activeId` is already the planner, that also early-returns without `renderChatFromHistory`, so the board header “Chat view” toggle can fail to repaint.

| `documentation/context.md` | Documents “focuses planner when returning from a task chat” — not from external chats |

**Repro sequence (primary):**

1. Activate any chat **outside** the orchestrate folder.
2. Click the orchestrate folder header → `openBoardGroup` (sidebar ~404–407).
3. Board fills `#chatArea`; `activeId` remains the external chat.
4. Click that external chat in the sidebar → `switchChat` early-return → board stays.
5. Click an in-folder task/planner chat (different id) → `switchChat` runs → board closes.
6. Now navigate to any external chat → works.

### Proposed Fix

**Do not implement yet** — recommended approach:

#### 1. Add `dismissActiveBoardView()` in `src/state/chat-groups.ts`

Central helper that:

- Resolves the open group via `activeBoardGroupId` (before clearing it)
- Sets that group’s `viewMode = 'chat'`
- Deletes `sessionState.activeBoardGroupId`
- Calls `disposeBoardSession()` (export or thin wrapper from `orchestrate-board.ts`)
- Calls `syncBoardViewChrome()` from `view-mode-toggle.ts`
- `scheduleSaveSessions()`

#### 2. Fix `switchChat` (`src/ui/sidebar.ts`)

```typescript
// Pseudocode — run BEFORE the activeId equality early return
const boardWasOpen = Boolean(sessionState.activeBoardGroupId);
const target = sessionState.chats.find((c) => c.id === id);
if (!target) return;

if (boardWasOpen) {
  dismissActiveBoardView(); // resets OPEN group, not target group
}

if (id === sessionState.activeId) {
  if (boardWasOpen) {
    renderChatFromHistory(target);
    syncViewModeToggleFromActiveChat();
    renderSidebar();
    scheduleSaveSessions();
  }
  closeMobileSidebar();
  applySidebarVisuals();
  return;
}

// ... existing switch body (remove duplicate board-clear block)
```

#### 3. Fix `openBoardGroup` (`src/state/chat-groups.ts`)

Always focus the planner when opening a board (align with `openBoardGroupFromHub`):

```typescript
if (plannerId && state.activeId !== plannerId) {
  state.activeId = plannerId;
  // clear planner unread, etc.
}
```

Remove the `active.boardGroupId === groupId` guard so external active chats don’t leave a mismatched `activeId`.

#### 4. Fix `closeBoardGroupView` (`src/state/chat-groups.ts`)

After state cleanup, call `renderChatFromHistory(plannerChat)` directly instead of `switchChat(plannerId)` to avoid the planner early-return.

#### 5. Tests (`test/ui/` — new `switch-chat-board-dismiss.test.mjs` or extend `view-mode-toggle.test.mjs`)

Cover the regressions above.
