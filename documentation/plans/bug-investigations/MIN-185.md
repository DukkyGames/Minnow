# MIN-185 Investigation

## MIN-185 — `/` in chat not working

### Verification Status

**Confirmed via static code analysis** (not runtime-tested in this investigation).

| Surface | Composer element | `mountSlashPicker` wired? | Default user path? |
|---------|------------------|---------------------------|-------------------|
| MinnowOS Desktop / Desktop Chat | `#desktopInput` | No | Yes (`#/desktop` default) |
| Chat app (`#/app/chat`) | `#chatAppInput` | No | Secondary |
| Code app | `#msgInput` | Yes (`main.ts` L303–306) | Requires opening Code from dock |

The slash **picker UI** is only initialized for `#msgInput`. With `isOsShellEnabled()` always `true` and the OS router defaulting to `#/desktop`, most users chat in composers that never receive slash-picker listeners.

**Note on “tools”:** The `/` menu is **skills-only** (`src/ui/skill-picker.ts`). Tool permissions use the separate sliders button popover (`#btnComposerTools` / `#btnChatAppTools` via `src/ui/composer-tools-popover.ts`). There is no slash autocomplete for tools in the codebase today — the issue title likely conflates the two features.

**Manual slash may still work:** `parseSlashCommand()` in `src/tools/loop.ts` runs on send regardless of picker state, so typing `/git-commit …` and sending might still activate a skill without the autocomplete menu.

---

### Root Cause

**Regression-by-omission after MinnowOS multi-composer architecture.** Step 13 added the slash picker only to the legacy Code composer. MinnowOS (#164) introduced `#desktopInput` and the Chat app added `#chatAppInput`, with routing centralized in `getActiveComposerSurface()` — but slash-picker mounting was never extended to those surfaces.

The desktop-window-shell plan explicitly calls this out as a known gap:

> “Dual composer paths — desktop uses `#desktopInput`; Code uses `#msgInput`; routing via `getActiveComposerSurface()` must stay in sync when adding features.”  
> — `documentation/plans/desktop-window-shell.md`

---

### Evidence

1. **Single mount site** — only Code composer is wired:

```303:307:src/main.ts
  const msgInput = document.getElementById('msgInput') as HTMLTextAreaElement | null;
  if (msgInput) {
    initComposerInput(msgInput);
    mountSlashPicker(msgInput);
  }
```

2. **Desktop composer has no slash wiring** — only resize + Enter-to-send:

```251:260:src/os/desktop-chat.ts
export function wireDesktopComposerControls(): void {
  const input = document.getElementById('desktopInput') as HTMLTextAreaElement | null;
  // ...
  input.addEventListener('input', () => {
    autoResizeDesktopComposer(input);
    syncDesktopComposerSendState();
  });
```

3. **Chat app composer同样 missing** — `bindStaticControls()` in `src/ui/chat-app.ts` (L415–426): `input`/`keydown` for send only; no `mountSlashPicker`.

4. **Composer surface registry documents three inputs** — `src/ui/composer-surface.ts` maps `code` → `msgInput`, `chat` → `chatAppInput`, `desktop` → `desktopInput`.

5. **Default route is desktop**, not Code — `parseOsHash()` / `hashForRoute()` in `src/os/router.ts` resolve unknown hashes to `{ view: 'desktop' }` / `#/desktop`.

6. **Picker anchor is fragile for multi-composer** — `ensurePicker()` uses the first `.input-wrap` in the document, not the active input’s parent:

```30:35:src/ui/skill-picker.ts
  const wrap = document.querySelector('.input-wrap');
  if (wrap) {
    wrap.appendChild(pickerEl);
  } else {
    document.body.appendChild(pickerEl);
  }
```

   Desktop uses `.mn-os-desktop-input-wrap`, so even a naive second `mountSlashPicker(desktopInput)` would attach the popover to the wrong (possibly hidden) Code composer wrap.

7. **Secondary issue (Code app only):** `detectSlashContext()` closes the picker when global `streaming` is true (`src/app-state.ts`), blocking `/` in Code while *any* chat is streaming — likely unintended with concurrent streams.

### Proposed Fix

**Primary (fixes MIN-185):**

1. **Refactor `skill-picker.ts` for multi-composer support**
   - Track mounts per `HTMLTextAreaElement` (or a single active picker that rebinds).
   - Anchor popover to `inputEl.parentElement` (add `position: relative` to `.mn-os-desktop-input-wrap` and `.chat-app-input` if needed), not `document.querySelector('.input-wrap')`.
   - Export a shared keydown helper already used by `handleKey` in `src/ui/input.ts`.

2. **Wire all composer surfaces at init**
   - `wireDesktopComposerControls()` → `mountSlashPicker(desktopInput)` + integrate `handleSkillPickerKeydown` in desktop `keydown` (before Enter-send).
   - `chat-app.ts` `bindStaticControls()` → same for `#chatAppInput`.
   - Keep existing `main.ts` mount for `#msgInput`.

3. **Optional consolidation** — add `initSlashPickers()` in `main.ts` that reads `DEFAULT_IDS` from `composer-surface.ts` and mounts all present textareas once.

**Secondary hardening:**

- Gate picker on **active chat streaming** (`isActiveChatStreaming()`), not global `streaming`.
- Add CSS for picker above desktop/chat composers (`z-index`, `position: relative` on wrap).

**Product clarification (not a bug fix unless requested):**

- Document that `/` is for **skills**; tools use the toolbar popover. A unified “skills + tools” slash menu would be new scope.

### Test Plan

1. **Desktop (default boot):** `npm start` → land on `#/desktop` → open desktop chat → type `/` → picker appears with built-in skills; arrow keys + Enter insert `/skill-id`; Escape closes.
2. **Chat app:** Navigate to `#/app/chat` → repeat `/` flow on `#chatAppInput`.
3. **Code app:** Open Code from dock → type `/` on `#msgInput` → picker still works (regression).
4. **Hub mode:** Empty chat with Vibe hub → type `/` in relocated composer → picker visible above input (not clipped).
5. **Send path:** Select skill from picker → send → `[skill: id]` footer in history; skill body in system prompt.
6. **Streaming:** Start generation in one chat → type `/` in another Code chat → picker should remain available (after secondary fix).
7. **Automated:** Add `test/ui/skill-picker.test.mts` (happy-dom) — mock catalog, dispatch `input` on each composer id, assert `#skillPicker` loses `hidden` class.
